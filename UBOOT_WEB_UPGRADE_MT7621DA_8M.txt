MT7621DA：U-Boot阶段网页升级OpenWrt操作说明
更新日期：2026-11-12

一、可以升级什么、需要什么条件

本次配套8M U-Boot支持在引导阶段运行独立网页恢复服务，不依赖OpenWrt/LuCI正常启动。
通过该网页上传的是OpenWrt系统镜像，擦写范围为firmware分区；不是通过网页更新U-Boot本身。

前提：设备已经单独安装本次配套的8M U-Boot：
构建提交：work_8M / 46c6edbdd059bc6df8a35df4feb43a076f8ae6bf
交付文件：u-boot-mt7621.bin，195,920字节
SHA-256：f14b80bb54c6f1b393e6aca87e2480af3a73ad782aad48693a5af8de0345edd5

仅通过LuCI刷入新OpenWrt不会更新U-Boot，旧引导不能因此自动获得本恢复功能。
若尚未安装配套引导，需先按受控引导更新流程处理，并备份每台设备的env/Factory。

二、准备正确的系统镜像

本次网页选择：mt7621da-5port-8m-squashfs-sysupgrade.bin
Windows位置：
F:\work-2026\mtk7621\work\step-v3\员工1_8M全功能演示方案\firmware\mt7621da-5port-8m-squashfs-sysupgrade.bin

文件大小：6,815,925字节
SHA-256：d8e38a09f5ad22b4b3359500d66934d2c80cc21aa05244ab9d587d309b03c39e
升级后OpenWrt版本：r11+1-823a7b4c
系统构建提交：work-8M / 823a7b4c1c254005fc055bec9de4ad2c4548ec6d

先在电脑核对SHA-256。不要在此流程选择u-boot-mt7621.bin、initramfs-kernel.bin、
full-flash-blank-factory.bin或16M固件。恢复页的合法镜像校验不代表任意第三方固件兼容。

三、电脑接线及IP

1. 使用稳定供电。设备如还能正常运行，先导出配置并保存重要业务账号。
   重要单机数据应另保存env/Factory；LuCI配置备份不是整片备份。
2. 电脑用网线直接连接设备LAN1至LAN4任一口，不能插WAN。
3. 电脑该以太网卡设为静态IPv4：192.168.1.2，子网掩码255.255.255.0。
   此直连网卡可不填网关和DNS，避免与其他网卡使用相同地址。
   如Wi-Fi/VPN导致访问走错路径，可临时断开这些连接。

四、进入U-Boot网页恢复

1. 断开路由器电源。
2. 按住RESET键，再给设备上电。
3. 继续保持按键，看到系统运行灯闪烁后松开。
   本版读取低有效GPIO18，保持低电平500ms触发，等待松开最多10秒。
4. 浏览器打开 http://192.168.1.1/ 。这是U-Boot恢复页，不是LuCI登录页，
   本版恢复页不要求管理员密码。WAN PHY4已隔离，LAN PHY0至3提供恢复访问。
5. 已接串口时，也可在自动启动菜单选择
   “Web recovery (LAN, 192.168.1.1)”进入同一恢复服务。
   本版还启用了自动启动失败返回后的Web恢复；不能将此等同于所有故障都可自动恢复。

五、上传、校验及写入

1. 在恢复页面选择第二节的8M sysupgrade文件，按页面提示上传并执行更新。
   此页面属于U-Boot，不沿用LuCI的Verify/Proceed按钮和“Keep settings”流程。
   在提交上传/更新操作前就要核对好文件，不能假定一定还有第二次确认。
2. 本版对大小、FIT哈希、8M板型/firmware分区及完整SquashFS进行检查，
   然后受限擦写firmware并回读验证。
3. 正常写入区域为0x050000至0x7fffff；首0x50000的U-Boot、env和Factory不在
   该系统恢复的写入范围。此操作不会更新U-Boot，也不会把8M芯片变成16M。
4. 开始写入后保持供电和网线连接，不按RESET，不重复提交。
   等待页面/串口提示完成并按流程重启。处理通常需要数分钟；
   网页暂时失联不能作为断电依据，固定等待时间也不能代替完成提示。
5. 恢复写入没有LuCI的配置归档及恢复步骤。应按需要重新配置业务准备，
   不能依赖旧overlay或原管理IP一定保留。

六、重启后检查

1. 正常启动后将电脑网卡恢复自动获取IP，重新获得地址，再访问设备管理页。
   默认地址为192.168.1.1；若实际保留了旧设置，使用实际LAN管理IP。
2. LuCI“状态 -> 概览”核对版本r11+1-823a7b4c，并按首次登录状态设置管理密码。
3. 检查LAN/WAN、上网方式、中英文界面及必要业务配置。新增业务默认不自启，
   Samba/OpenVPN/IPsec/QoS配置完成后再按需启用。
4. 可选SSH检查：

   cat /etc/openwrt_version
   cat /tmp/sysinfo/board_name
   cat /proc/mtd
   df -h /overlay

   board_name应为mt7621da-5port；firmware长度007b0000、擦除块00010000。
   rootfs_data预计总长度1216KiB，实际可用空间会因文件系统和配置占用而更小。

七、进不了页面或校验失败

- 先确认确实安装了配套U-Boot；仅刷OpenWrt系统不满足此前提。
- 检查网线是否在LAN、网卡是否为192.168.1.2/24、链接灯是否亮及浏览器是否走代理。
- 检查RESET时序，按上面方法重新进入；已开始Flash写入时不得用重复断电尝试排查。
- 校验失败时核对镜像SHA-256、8M板型和文件用途，停止错误上传，不绕过校验。
- 如仍无法恢复，保留页面/串口信息再定位；不要用空片样板覆盖已有单机数据。

本说明依据本次U-Boot源码与构建结果编写；本轮没有实板网页刷写记录。
本次仅补充操作文档，现有固件二进制、构建提交、系统版本及SHA-256保持不变。
